# OpenArm 1.0 MuJoCo 拖动与实体控制

> **YANGHAO / YANGHAO_OPENARM / YANGHAO_CONTROL**
>
> 杨浩当前版本的快速启动、操作和安全规则见
> [YANGHAO_OPENARM_CONTROL.md](YANGHAO_OPENARM_CONTROL.md)。本文保留完整实现、
> 迁移和验证细节。

当前实机已经确认是 OpenArm 1.0。程序默认加载项目内固定的官方 v1 MJCF：
`models/openarm_v1/scene.xml`。不得使用已安装 Python 包中的 v2 Cell 模型控制
这台机械臂。

## 迁移记录（2026-07-28）

最初按 OpenArm 2.0 配置时，实机标定姿态与 MuJoCo 出现明显差异：实机双臂
接近下垂，但仿真双臂向内蜷缩。最终通过夹爪结构和官方模型对比，确认实体硬件
是 OpenArm 1.0：

- v1 使用平行连杆/滑轨夹爪；
- v2 使用紧凑型 pinch gripper，并采用不同末端模型；
- 当时本机只安装了 `openarm-mujoco 2.0.0`，因此程序一直加载错误模型。

完成的迁移工作：

- 从 Enactic 官方 `openarm_mujoco` 仓库固定 v1 MJCF 与 mesh 到
  `models/openarm_v1/`；
- `src/openarm_teleop/interactive_mujoco_ee_drag.py` 增加 `--model-version v1|v2`，默认 `v1`；
- v1 末端控制帧改为 `openarm_right_hand_tcp` /
  `openarm_left_hand_tcp`，类型为 MuJoCo body；
- 保留原有双臂选择、鼠标拖动、相机控制、目标限速和 IK 安全过滤；
- 新增 v1 实机只读检查 `verify_real_mujoco_alignment_v1.py`；
- 实体启动脚本固定传入 `--model-version v1`；
- 单独处理 v1 夹爪的电机转角与 MJCF 滑块位移单位差异。

固定模型来源为官方仓库提交
`8955afb54e4adfb59a236e2b4d15192b7a02865c`（2026-07-27），许可证保存在
`models/openarm_v1/LICENSE`。

## 当前接口映射

- 右臂：`can0`
- 左臂：`can1`
- 交互实体控制配置：`config/openarm_safe_raw_zero.yaml`

本机电机是在双臂基本竖直下垂、对应 MuJoCo `qpos=0` 的姿态写入零位，
因此该配置的 `joint_offsets` 为全零。不得改回官方 Cell 治具使用的 offset，
否则仿真会表现为双臂向内蜷缩，反向控制指令也会使用错误坐标。

每次接线变化后都必须重新检查接口映射，不得只依据 USB 插入顺序推断。

清空工作空间、固定底座并确保急停触手可及，然后启动：

```bash
cd /home/robin/open_arm
./scripts/launch/run_interactive_real.sh --confirm-hardware
```

启动流程：

1. 检查 `can0`、`can1` 均存在且为 `UP`；
2. 只读获取双臂关节反馈；
3. 检查反馈稳定、数值有限且位于配置关节限位内；
4. 用实机关节位置初始化 MuJoCo 和 IK；
5. 打开窗口，保持两条机械臂失能。


## VIVE + SteamVR 纯仿真遥操作

> **YANGHAO / YANGHAO_VIVE_SIM / YANGHAO_STEAMVR / YANGHAO_VIVE_BIMANUAL**
>
> 关键词说明：本节记录 2026-07-29 已实测通过的 OpenArm 1.0 双手柄、双臂、
> 夹爪和姿态遥操作版本。搜索 `YANGHAO_VIVE_BIMANUAL` 可直接定位到本节。

该入口只加载 OpenArm 1.0 MuJoCo、严格 IK 和 OpenVR，不创建 CAN 驱动：

```bash
cd /home/robin/open_arm
./scripts/launch/run_vive_mujoco_sim.sh
```

启动前必须满足：

- Ubuntu 登录会话为 Xorg（`echo $XDG_SESSION_TYPE` 输出 `x11`）；
- SteamVR 正在运行；
- 头显、Base Station 2.0 和两个手柄在 SteamVR 中为绿色；
- 手柄位姿有效，而不只是无线连接。

操作：

- `1`：选择左臂，使用左手柄；
- `2`：选择右臂，使用右手柄；
- 直接按下左/右手柄侧握键即可控制对应机械臂；两只侧键可以同时按住，左右臂会
  在同一个仿真循环内分别更新目标并同时运动；
- 按住对应手柄的侧握键：以按下瞬间为相对零点，末端位置和夹爪方向跟随；
- 松开侧握键：冻结当前目标；
- 按下手柄触摸板上半区：逐渐张开该侧夹爪；
- 按下手柄触摸板下半区：逐渐闭合该侧夹爪；松开触摸板即保持当前开度。左右
  夹爪可独立或同时操作，夹爪输入不要求按住侧握键；
- `R`：目标复位到当前仿真末端；
- `Space`：暂停/恢复 IK；
- `Esc`：退出。

默认位移比例为 `1:1`。仿真每帧平移/旋转推进上限为 `10 mm`/`2°`；目标循环
最高 60 Hz，理论上限约 `0.6 m/s`/`120°/s`。方向使用手柄相对
旋转映射到夹爪四元数，接合瞬间不会跳变。仿真初始 J4 弯曲 `45°`，避免 v1
双臂完全下垂零位的运动学奇异；这不会修改实机零位。

手柄位姿丢失时程序立即释放离合并冻结目标。目标不可达、关节分支跳变或 IK
误差过大时，程序自动执行等效 `R`：把目标球复位到当前有效末端，同时把当前
手柄位姿重新设为相对零点。侧握键仍按住时离合保持开启，可直接继续移动；只有
主动松开侧握键才停止跟随。可调参数：

```bash
./scripts/launch/run_vive_mujoco_sim.sh --scale 1.0 --max-offset 0.25 \
  --elbow-bend-deg 45 --position-step-mm 10 --orientation-step-deg 2 \
  --gripper-step-mm 1
```

上述速度参数仅用于仿真，当前版本支持双臂同时控制。尚未连接实体机械臂，
不得把该纯仿真入口误认为实体遥操作入口。实体模式必须在关节命令层另设关节
速度、加速度、单周期步长与力矩限制，并持续执行关节限位和碰撞检查。

当前已验证的功能：

- 两只 VIVE 手柄位置与三轴方向分别映射到左右夹爪末端位姿；
- 左右侧握键为独立离合，可单臂操作，也可双臂同时跟随；
- 单侧 IK 失败时自动执行等效 `R`，复位该侧目标和手柄相对原点，保持侧键
  跟随状态，不中断另一侧；
- 左右触摸板上/下半区分别控制对应夹爪张开/闭合，松开即保持；
- 夹爪状态独立于 IK 保存，不会被下一帧手臂解算覆盖；
- 默认仿真平移、旋转和夹爪步长分别为 `10 mm/帧`、`2°/帧` 和
  `1 mm/帧`。

### YANGHAO_VIVE_REAL：双臂实体控制入口

> **YANGHAO / YANGHAO_VIVE_REAL / YANGHAO_VIVE_BIMANUAL_REAL**

实体入口与纯仿真入口分离，避免误启动：

```bash
cd /home/robin/open_arm
./scripts/launch/run_vive_mujoco_real.sh --confirm-hardware
```

启动时只读取双臂位置并初始化 MuJoCo，随后再次发送失能命令；不会自动运动。
窗口打开后：

- `E`：使能/失能双臂。每次使能前都会失能、重新读取实机位置并让仿真与实机
  对齐，因此不会执行旧的仿真目标；
- `P`：立即失能，并重新读取双臂位置同步仿真；
- 使能后操作与纯仿真一致：左右侧握键独立控制左右臂位姿，两个侧键可同时按；
- 触摸板上/下半区分别张开/闭合对应实体夹爪；
- 松开侧握键后不再更新该臂目标，电机保持最后一次指令位置；
- 关闭窗口、`Esc`、异常或 `Ctrl+C` 都会在清理阶段失能双臂。

默认实体安全参数：

```text
command_hz           = 20 Hz
max_joint_step       = 0.002 rad/周期（理论约 0.04 rad/s）
max_tracking_error   = 0.15 rad
VIVE scale           = 0.6
single clutch offset = 0.15 m
IK position step     = 4 mm/帧
IK orientation step  = 0.75°/帧
gripper step         = 0.4 mm/帧
```

每个 CAN 发送周期都会先执行：

1. 检查目标和下一小步是否为有限数值并位于配置关节限位内；
2. 将每个关节的单周期变化限制为 `max_joint_step`；
3. 在 MuJoCo 中沿当前姿态到下一小步插值，预测自碰撞、左右臂碰撞及模型中已有
   环境几何体碰撞；
4. 发送后读取反馈，检查反馈有效性和最大跟踪误差；
5. 若侧键仍按住时对应手柄丢失追踪，立即失能双臂；
6. 任一侧失败时立即失能双臂，输出 `[hardware] SAFETY STOP`。

预测碰撞只能识别 MuJoCo 模型中存在的几何体，无法看到现场桌面、人员、线缆等
未建模障碍物。首次测试必须清空工作区、降低速度、保持急停可触及，并先只使能
而不按侧握键，确认机械臂保持原姿态。可在允许范围内覆盖参数：

```bash
./scripts/launch/run_vive_mujoco_real.sh --confirm-hardware \
  --command-hz 20 --max-joint-step 0.001 \
  --max-tracking-error 0.12 --scale 0.5 --max-offset 0.10
```

程序不会自动把实机移动到 MuJoCo `home`。必须先确认画面姿态和实机姿态一致，
再使能机械臂。

### YANGHAO_VIVE_ABSOLUTE：人体固定坐标绝对位姿方案

> **YANGHAO / YANGHAO_VIVE_ABSOLUTE / YANGHAO_VIVE_ABSOLUTE_REAL**

原有 `run_vive_mujoco_sim.sh` 和 `run_vive_mujoco_real.sh` 是“按下侧握键时重新
锚定”的相对增量方案，已完整保留。绝对位姿方案使用独立文件和独立入口，不会
改变旧方案的操作语义。

纯仿真：

```bash
cd /home/robin/open_arm
./scripts/launch/run_vive_absolute_mujoco_sim.sh
```

该入口默认保留左右臂独立锚点映射。需要“两个手柄 tip 位于同一点时，两个原始
末端目标也位于同一点”的共享绝对工作空间时，使用：

```bash
./scripts/launch/run_vive_shared_mujoco_sim.sh
```

共享模式使用一个人体—机器人平移、同一坐标轴和同一缩放比例；左右只保留各自
的安全执行状态，不再保留下垂姿态的左右方向锚点。VIVE Wand 的 OpenVR
tracking origin 不是握把中心，
程序会读取渲染模型的 `tip` 组件并修正到手柄前端。本机
`vr_controller_vive_1_5` 的 tip 偏移约为 `[0, -10, -7] mm`。两个原始目标可
完全重合，但安全执行目标会在预测到夹爪、手臂或躯干碰撞前停止。

共享模式的方向使用固定、可重复的三轴对应，而不是标定姿态的相对方向：

```text
VIVE tip -Z（圆环指向） → OpenArm TCP +Z（夹爪前向）
VIVE tip +X（手柄横向） → OpenArm TCP +Y（手指开合轴）
VIVE tip +Y（触摸板法向）→ OpenArm TCP +X
```

该轴变换是正交右手坐标变换，行列式为 `+1`。左右手使用完全相同的规则；标定
第二步的下垂姿态在共享模式中只用于确定空间平移，不再决定夹爪方向。

共享模式只需要三步标定：

1. 头显确定正前方向；
2. 双臂自然下垂，确定共享空间平移参考；
3. T-Pose 计算人体有效臂长和统一缩放比例，随后立即完成并给出最长振动。

共享模式不会显示或采集90°弯肘步骤。原 `anchored` 人体比例模式仍保留完整
四步流程，以便记录大小臂估计。

启动后确保头显和两个手柄都正常追踪，松开两个侧握键，按照日志提示连续完成
四个姿态，每个姿态稳定后按一下任意手柄的扳机键并松开（键盘 `C` 仍可备用）：

1. **确定正前方向**：头显无需佩戴，可放置或挂起，只要朝向人体正前方并保持
   `TRACKING`；程序只记录头显水平朝向，不使用头显位置；
2. **双臂自然下垂**：手腕自然，记录手柄到竖直夹爪的方向偏移，并把当前机器人
   末端作为动作锚点；
3. **T-Pose**：双臂水平向左右伸直，估算左右有效臂长，并用“机器人有效臂长 /
   人体有效臂长”自动计算工作空间比例；
4. **90°弯肘向前**：上臂下垂、肘靠近躯干、前臂水平向前，估算人体大臂和
   小臂比例。

肩部中心由 T-Pose 双手中点估算，左右肩位置由肩宽分开；有效单臂长度近似为
`(双手展开距离 - 肩宽) / 2`。默认肩宽为 `0.38 m`，最好实际测量后启动，例如：

```bash
./scripts/launch/run_vive_absolute_mujoco_sim.sh --shoulder-width 0.41
```

每一步采集成功后两只手柄都会立即振动，头显内的 SteamVR 通知会显示已完成
步骤和下一个姿态；电脑端独立的“OpenArm VIVE 标定向导”窗口同时保留完整清单
和实时追踪状态。最终日志出现 `[absolute] CALIBRATED` 后会给出最长振动确认，
此时才允许绝对跟随。完成后头显可继续放置或挂在脖子上；不要再按扳机进行
标定，否则会从第一步重新开始。

标定之后，人体坐标的前、左、上分别映射到机器人世界坐标 `+X、+Y、+Z`。
后续目标由“手柄当前绝对位姿与标定位姿的差”计算，头显位置从始至终不参与
控制，头显方向也不再逐帧更新。再次开始四步流程才会重新标定。

- `K`：明确开始或重新开始一轮标定；实机模式会先失能双臂；
- 任意手柄扳机键：仅在 `K` 已启动的标定流程中依次采集姿态；每步必须松开
  后再按，完成时双手柄振动。标定完成后扳机不会再意外重启标定；
- `C`：标定流程中的扳机备用采集键，不能单独重新开始标定；
- 左/右手柄侧握键：仅允许对应机械臂跟随，不会重新设置锚点；
- 两个侧握键可同时按住，双臂每帧交替求解先后顺序；
- 触摸板上/下：对应夹爪张开/闭合；
- `H`：取消双臂跟随并让双臂限速回到仿真安全初始姿态；夹爪开度保持不变。
  复位后先松开两个侧握键，再按住需要控制的一侧；
- `R`：只把当前所选手臂的目标复位到其当前末端，不会让机械臂回初始姿态；
- `Esc`：退出。

蓝/橙色半透明小球表示手柄映射得到的原始目标，实色末端目标表示当前安全可执行
目标，两者之间的细线表示被速度、可达性或碰撞约束截去的部分。IK 无解、关节
越限或预测到手臂碰躯干、双臂互碰、自碰时，程序尝试半步、四分之一步和逐轴
安全投影；如果这一帧完全没有安全增量，就保持在上一个安全点。侧握键仍保持
有效，下一帧会继续求解，不需要松开重按，也不会修改绝对标定。

每个目标还显示红、绿、蓝三轴方向：较长的半透明方向轴是手柄映射得到的原始
姿态，较短的明亮方向轴是 IK 和碰撞检查后当前实际执行的姿态。两组轴未重合
表示姿态仍在限速追赶或被安全投影。共享模式启动脚本当前设置的位置限速为每帧
`9 mm`、姿态限速为每帧 `3.5°`；独立锚点入口仍使用默认 `6 mm` 和 `2.5°`。
侧握跟随期间使用高姿态权重；松开再按侧握键不会改变方向锚点。

程序默认自动计算臂长比例；三个 `scale` 参数是自动比例之上的方向修正系数，
默认均为 `1.0`。例如只把上下动作缩小到自动比例的 80%：

```bash
./scripts/launch/run_vive_absolute_mujoco_sim.sh \
  --scale-forward 1.0 --scale-left 1.0 --scale-up 0.8
```

实体入口：

```bash
./scripts/launch/run_vive_absolute_mujoco_real.sh --confirm-hardware
```

共享绝对工作空间的 OpenArm 1.0 实体入口：

```bash
./scripts/launch/run_vive_shared_mujoco_real.sh --confirm-hardware
```

共享入口使用三步标定，默认只读取实机位置并保持电机失能。确认仿真姿态、原始
目标和安全目标都正确，且两个侧握键均已松开后，再按 `E` 同时使能双臂。其
实机输出当前采用每帧 `9 mm`、`3.5°` 的笛卡尔目标追赶。实体模式中的
MuJoCo 机械臂不再瞬间跳到 IK 终点，而是显示本周期实际发给电机的同一组限速
关节指令；半透明原始目标和明亮安全目标仍可显示尚未完成的追赶距离。底层 CAN
使用 `40 Hz`，J1–J7 单关节单周期最大增量为 `0.0125 rad`（约
`0.50 rad/s`），并使用 `3.0 rad/s²` 的加速度限制。每一步仍经过实机关节
限位和整段碰撞预测。

J8 夹爪电机使用独立的更低限速 `0.001 rad/周期`（40 Hz 下约
`0.04 rad/s`）。这是因为本机左 J8 在 `0.16 rad/s` 命令下实测只能跟到约
`0.061 rad`，指令累计到 `0.212 rad` 后产生 `0.1508 rad` 跟踪误差并触发
失能。夹爪仍保持 `0.001 rad/周期` 的独立限速，夹爪跟踪误差保护保持不变。

共享实机入口的 J1–J7 在 YAML 硬限位内保留 `0.04 rad`（约 `2.29°`）软限位
余量；程序通用默认值仍为 `0.05 rad`。
原因是 MuJoCo 使用精确弧度值（例如 J7 的 `π/2 = 1.5707963268`），YAML
使用截断值（`1.570796`）；没有余量时，仿真合法的边界姿态可能因约
`3.27e-7 rad` 的数值差被实机驱动判为越限。现在 IK 候选在进入软限位带前
会被安全投影，发送层还会再次钳制；YAML 硬限位和驱动检查保持不变。必要时可
通过 `--joint-limit-margin` 调整，但实机入口只接受 `0.02–0.15 rad`。

SteamVR 偶尔会让手柄出现单帧 `NO-POSE`。实机版现在会在追踪丢失的第一帧
立即冻结该手臂输出，但保留默认 `0.30 s` 恢复窗口；定位在窗口内恢复时可继续
控制，持续丢失超过窗口才会双臂失能。可通过 `--tracking-loss-timeout` 在
`0.10–0.75 s` 范围调整。该窗口不会继续使用旧手柄位姿发送运动。

共享实机快捷键：

- `E`：双臂使能/失能；再次按下会取消回位并立即失能；
- `P`：失能双臂、从实机反馈同步仿真并清除标定；
- `H`：仅在双臂已经使能时启动限速安全回位。实机指令真正收敛前手柄不能重新
  接管；完成后须先松开两个侧握键；
- `Esc`：退出程序，并在清理阶段失能双臂。

`H` 不是急停。发生异常运动、碰撞风险或有人进入工作区时必须使用实体急停。
软件检测到追踪丢失、反馈异常、关节越限、跟踪误差超限或预测碰撞时，会输出
`[hardware] SAFETY STOP` 并失能双臂。

本机达妙电机现场灯色：绿色表示使能，红色表示失能。按 `E` 成功后应转为
绿色；若随后变红，应立即查看日志中的 `SAFETY STOP` 或 `ENABLE rejected`，
不要仅凭灯色继续重复使能。

实体模式的严格顺序是：

1. 启动时读取实机 J1–J8 并同步 MuJoCo，电机保持失能；
2. 比较仿真与实机姿态，确保工作区清空且急停可触及；
3. 松开两个侧握键，按日志完成正视、下垂、T-Pose 和90°弯肘四次 `C`；
4. 按 `E` 同时使能双臂，此时不应产生位置跳变；
5. 先只按一侧侧握键并移动几毫米，确认方向后再测试另一侧和双臂；
6. `E` 失能；`P` 会失能、重新读取实机姿态并清除标定，随后必须重新按 `C`。

实体默认使用自动臂长比例、笛卡尔目标速度为每帧 `4 mm`，底层 CAN
命令频率 `20 Hz`、每周期单关节最大变化 `0.002 rad`。每次发送前还会对下一
关节小步执行物理限位和 MuJoCo 插值碰撞检查；反馈无效、跟踪误差超限、侧握键
按住时丢失定位或任一安全检查失败，都会立即失能双臂。模型之外的人员、桌面和
线缆仍无法检测，不能用软件检查替代急停和现场观察。

程序在启动时读取一次双臂实机姿态，并用它初始化 MuJoCo。此后可用 `D` 单次
执行当前仿真姿态，也可用 `F` 开关连续跟随。

## 3. 机械臂选择与目标操作

当前版本只打开一个项目原生使用的 `mujoco.viewer.launch_passive` 窗口。展开
右侧 **Control** 区域即可看到左右臂执行器滑条；这些是 MuJoCo 自带 UI，直接
修改 `data.ctrl`。v1 MJCF 原本没有为 J1–J7 写
`ctrlrange`，程序运行时会用对应 joint range 补全，因此原生面板可以显示并
控制全部关节执行器。

画面中的绿色大球是当前活动臂末端目标，蓝色小球是另一臂目标。使用 MuJoCo
原生物体操作：

- 双击目标球：选中目标；
- `Ctrl + 右键拖动`：平移选中的目标；
- `Ctrl + 左键拖动`：旋转选中的目标；
- 普通左键拖动、右键拖动和滚轮：使用 MuJoCo 原生视角操作。

拖动原生 Control 滑条会更新仿真关节，并同步末端目标，避免 IK 立即拉回。
实体连续跟随开启时，关节目标仍经过约 `20°/s` 限速、实机关节限位和逐步碰撞
预测，不会将大幅滑动一次发送给电机。原生面板也会显示手指执行器，但当前实体
跟随仍保持夹爪不动。

- `1`：选择左臂；
- `2`：选择右臂；
- `Tab`：切换活动臂，实体模式下会先失能原活动臂；
- `R`：把目标恢复到活动臂当前末端位置；
- `Space`：暂停或恢复 IK；
- `Esc`：退出，实体模式下同时失能机械臂。

## 5. 实体模式使能与慢速控制

- `E`：使能或失能当前选择的机械臂；
- `F`：开启或关闭连续跟随，实体臂随仿真关节姿态逐步运动；
- 单击 `D`：让当前已使能的实体机械臂慢速移动到当前仿真关节位置；
- `P`：自动失能并重新读取双臂实机姿态，将仿真复位到实体当前位置；
- 到达后停止更新位置指令，电机保持目标位置；
- 切换活动臂、关闭窗口或程序异常退出：失能当前机械臂。

`D` 是一次性的“执行当前仿真姿态”命令，不需要持续按住。仿真目标不可达或
IK 尚未收敛时，程序会拒绝执行。

`F` 开启后，每个发送周期只检查并发送从上一指令到下一小步的命令，不会直接
跳到远处目标。若 IK 判断末端目标不可达，程序自动执行等效 `R`：把目标球复位
到当前可达末端位置，并保持连续跟随开启。下一步预测碰撞、实机关节越限、通信
异常、切换机械臂或失能仍会关闭跟随。再次按 `F` 也可主动关闭。连续跟随不控制
v1 夹爪。

`D` 不再使用固定的目标距离门槛。执行前程序会以最大约 `0.01 rad` 的关节
间隔，对实机当前位置到仿真目标的整条关节线性轨迹采样。每个采样点都必须满足
J1–J7 限位，并且活动臂不得与自身、另一臂、底座或环境发生 MuJoCo 碰撞。
v1 闭合夹爪两指之间的预期接触会被忽略。轨迹通过后，无论距离大小都继续使用
慢速指令限制执行。

初始实体限速：

- 指令频率：`40 Hz`；
- 每周期最大关节变化：`0.0087 rad`；
- 等效单关节最大速度约：`0.348 rad/s`，即 `19.9°/s`。

该限速位于交互程序中；驱动内部的关节绝对限位和相邻指令增量保护仍同时生效。

OpenArm 1.0 实体夹爪反馈是电机转角，而 MJCF 使用 0–44 mm 直线滑块。当前界面
尚未提供夹爪目标操作，因此按 `D` 时只执行 J1–J7，夹爪保持当前物理角度。

  v1 实体交互；当前入口只使用 `config/openarm_safe_raw_zero.yaml`。

## 8. IK 安全实现

交互程序使用项目内的 `src/openarm_teleop/safe_kinematics.py`，不再直接使用已安装
`openarm_control` 中会在受限求解失败后执行 `limits=[]` 的回退路径。

严格 IK 的规则：

- 每次求解始终携带 MuJoCo 关节限位；受限问题无解时直接拒绝目标；
- 每周期以当前关节角作为姿态正则目标，优先选择离当前姿态最近的冗余解；
- 积分结果逐关节再次检查硬限位；
- 仅将小于 `1e-5 rad` 的边界浮点噪声夹回限位；
- 任一关节单次求解变化超过 `0.06 rad` 时，判定为分支跳变并回滚；
- `D` 执行前检查整条关节插值轨迹的限位与 MuJoCo 碰撞；固定距离门槛已取消；

末端任务同时包含位置误差和朝向误差。姿态权重决定求解器为了保持/改变夹爪
方向，愿意让多少关节参与补偿：

- 普通左键平移：姿态权重 `0.15`，位置优先，允许少量朝向误差以减少绕肘、
  翻腕和多余关节动作；
- 右键旋转及其后约 `0.3 s`：姿态权重 `1.0`，严格跟随用户指定的末端朝向；
- 非活动臂：姿态权重 `1.0`，保持其当前末端位姿。

OpenArm 1.0 双臂下垂零位接近运动学奇异位形。在该姿态保持夹爪方向完全不变时，
部分笛卡尔方向本来就不可达；目标变红或被拒绝属于正确行为，不应通过取消限位
强行求解。

## 9. 首次实体操作顺序

1. 启动实体模式，但不要按 `E`；
2. 比较 MuJoCo 与实机双臂初始姿态；
3. 按 `1` 或 `2`，只选择一条机械臂；
4. 按 `R`，确保目标位于当前末端；
5. 在仿真中把末端目标拖动约数毫米，等待 IK 收敛；
6. 按 `E` 使能该臂，观察是否保持静止；
7. 先单击 `D` 验证小动作；确认无误后按 `F` 开启连续跟随；
8. 检查实机、画面、日志和 CAN 状态；
9. 确认无异常后再逐步扩大范围；
10. 测试结束按 `E` 失能，再按 `Esc` 退出。

发生方向错误、突然运动、振动、异常声音、通信丢失、红灯或接近机械限位时，
立即按急停，并切断使能。
